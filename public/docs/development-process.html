Development Process

1. Code Management

  • All source code stored in a private GitHub repository
  • Branch protection enabled on main — direct pushes blocked
  • Pull request reviews required for all changes before merge
  • Automated CI checks run on every commit (tests + security scans)
  • Signed commits encouraged for all contributors

3. Code Review Process

All code changes go through a four-stage review gate before deployment:

  1. Developer self-review — author verifies diff before opening PR
  2. Peer code review — at least one approved review required
  3. Automated security scanning — GitHub Dependabot (dependencies) + CodeQL (code analysis)
  4. Deployment approval — sign-off from technical lead before merge to main
Full review standards are documented in CODE_REVIEW_POLICY.md in the repository root.

4. Security Standards

Authentication & Authorization

Identity
  • JWT-based auth via Firebase
  • Secure session management
  • Multi-factor authentication (MFA) supported
Access Control
  • Row Level Security (RLS) on all tables
  • Role-based access control (RBAC)
  • Hospital-scoped data isolation

Data Protection

Encryption
  • At rest: AES-256
  • In transit: TLS 1.3
  • HIPAA-compliant infrastructure
Backup & Retention
  • Automated daily backups
  • 7-year audit log retention
  • Point-in-time recovery (PITR)

Vulnerability Management

  • Automated dependency scanning via GitHub Dependabot
  • Static code analysis via GitHub CodeQL on every push
  • Third-party penetration testing (WorkStreet — May 2026)
  • Responsible disclosure via security.txt
  • Security patches prioritised by severity within defined SLAs

6. Deployment Process

  1. 1
    Code committed to GitHub — feature branch opened, PR created
  2. 2
    Automated tests run — unit, integration, and type checks
  3. 3
    Security scans complete — Dependabot + CodeQL must pass
  4. 4
    Manual review and approval — peer review + technical lead sign-off
  5. 5
    Deploy to Netlify — merge to main triggers automatic build
  6. 6
    Post-deployment verification — smoke tests on live environment
  7. 7
    Rollback capability maintained — previous build retained for instant revert

7. Monitoring & Logging

  • Firebase database monitoring — query performance and anomaly detection
  • Netlify deployment logs — build history, function logs, and error tracking
  • Application error tracking and real-time alerting
  • Access logs with 7-year retention for compliance
  • Audit logs for all sensitive operations (uploads, shares, admin actions)
All hospital admin actions — including result uploads, patient lookups, and profile changes — are written to an immutable audit log scoped per facility and per admin user.

8. Incident Response

In the event of a suspected security incident, the incident response plan defines containment, investigation, notification, and remediation steps. Response SLAs by severity:

SeverityResponse TimeExamples
Critical Within 24 hours Data breach, auth bypass, PII exposure
High / Medium Within 1 week Privilege escalation, dependency CVE
Low / Info Within 2 weeks Information disclosure, minor misconfig
Full procedures are documented in INCIDENT_RESPONSE_PLAN.md in the repository. Report vulnerabilities via security@myhealthstatus.org or security.txt.
